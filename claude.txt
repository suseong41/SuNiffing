 [P0] A-1  CSA 정수 언더플로우 -> 루트 스택 오버플로우     [실측] == 해결됨  ==
--------------------------------------------------------------------------------
 위치 : runner.cpp 181-218 (CSA 분기)
 핵심 : tagLen 이 int16_t(L182) 인데 (capLen - rdt->len - 36) 을 담는다.
        공격자가 타겟 BSSID 로 위조한 "짧은 비콘"(capLen < rdt->len+54)을 쏘면
        tagLen 음수 -> remainLen(uint16_t) 이 거대값으로 래핑 ->
        고정 newPacket[4096] 에 상한검사 없이 memcpy => 스택 스매싱.

 실측 (실제 산술 그대로 재현):
   입력                 tagLen(i16)  remainLen(u16)  최대기록   결과
   정상 비콘 200B        146          96             205        ok
   위조 42B 프레임       -12          65524          65583      오버플로우
   대형 비콘 4100/5000B  4046/4946    3996/4896      4105/5005  오버플로우
   rdt>cap               -56          65480          65601      오버플로우

 도달조건 : Act::CSA 활성 + 타겟 BSSID 로 위조 비콘 1장. (chkBeacon 은 fc 첫옥텟
            0x80 이면 통과하므로 본문이 짧아도 트리거됨)

 수정 방향 (L181-202 교체):
   - 모든 길이 산술을 부호있는 넓은 타입(long/ptrdiff_t)으로.
   - 음수/상한 가드 후 진행. newPacket 은 4096 상한검사 또는 동적할당.

   long capLen = header->caplen;
   // 진입 가드: radiotap + MAC + 비콘 고정부가 캡처 범위 안에 있어야 함
   if (capLen < (long)(rdt->len + sizeof(ST_WL) + sizeof(ST_BC_COMMON))) continue;

   int  packetCount = presentCount(packet);
   bool isFcs = hasFcs(packet, rdt, packetCount);
   int  fcs   = isFcs ? 4 : 0;

   const u_char* beaconTagPacket =
       packet + rdt->len + sizeof(ST_WL) + sizeof(ST_BC_COMMON);
   long tagLen = capLen - rdt->len - (long)sizeof(ST_WL)
                 - (long)sizeof(ST_BC_COMMON) - fcs;
   if (tagLen < 0) continue;

   long insertTagLoc = capLen - fcs - tagLen
                       + getInsertTagLoc(beaconTagPacket, (int)tagLen, 37);
   long remainLen    = capLen - insertTagLoc - fcs;
   long newPacketLen = capLen + 5 - fcs;
   if (insertTagLoc < 0 || remainLen < 0) continue;

   long needed = insertTagLoc + 5 + remainLen;        // memcpy 총 기록량
   if (needed > 4096 || newPacketLen > 4096) continue; // 또는 std::vector<uint8_t> 동적할당
   uint8_t newPacket[4096];
   ...
   pcap_sendpacket(pcapTX, newPacket, (int)newPacketLen);

 부수 : L216 csaTag 의 (uint8_t)currentCmd.channel 절단 -> A-8(데몬 입력검증)과 함께
        channel ∈ [1,14] 검증 추가 권장.

 [P0] A-2  타겟-STA 지정 CSA 경로 헤더 손상 (off-by-10)   [추적, report 누락] == 해결됨 ==
--------------------------------------------------------------------------------
 위치 : runner.cpp 205-210 (stationMode 분기)
 핵심 : 특정 STA 지정 시 DA 를 STA MAC 으로 바꾸려는 의도인데, 3번째 memcpy 의
        "목적지" 오프셋이 +10 만큼 빠져 방금 쓴 fc+duration+DA 를 덮어쓴다.

   memcpy(newPacket + rdt->len + 4, currentCmd.target_st.mac, 6);            // DA 자리
   memcpy(newPacket + rdt->len,     packet + rdt->len + 10,                  // <-- dest 틀림
          insertTagLoc - rdt->len - 10);

 결과 : 새 프레임의 fc 가 원본 Address2 첫바이트로 덮여 헤더 깨짐. 이후 insertTagLoc
        기준 csaTag 삽입 오프셋도 10B 어긋남. (브로드캐스트 CSA = else 분기는 정상,
        그래서 기존 테스트에서 안 걸린 것으로 보임)

 수정 :
   memcpy(newPacket + rdt->len + 10, packet + rdt->len + 10,
          insertTagLoc - rdt->len - 10);
   // 추가 가드: if (insertTagLoc < rdt->len + 10) continue;  // 음수 길이 방지
   //           (A-1 의 needed/상한 가드와 함께 적용)

 [P0] A-3  짧은 802.11 프레임 OOB read (루트)            [추적] == 해결됨 ==
--------------------------------------------------------------------------------
 위치 : runner.cpp 174-177 (+ 이후 chkBeacon/bssid/getStationInfo da,sa)
 핵심 : rdt->len 은 로컬 생성이라 신뢰 가능하나, 802.11 본문은 공격자 제어.
        runt 관리프레임(802.11 부분 < 24B)을 보내면
          const ST_WL* wl = (const ST_WL*)(packet + rdt->len);  // 24B 구조체
        의 wl->bssid(offset+16) 등이 caplen 을 넘어 OOB read -> 루트 크래시(DoS).

 수정 (L174 앞):
   if (header->caplen < sizeof(ST_RDT)) continue;
   const ST_RDT* rdt = (const ST_RDT*)packet;
   if (rdt->len < sizeof(ST_RDT) ||
       (size_t)rdt->len + sizeof(ST_WL) > header->caplen) continue;
   const ST_WL* wl = (const ST_WL*)(packet + rdt->len);
   // 이 가드 하나로 chkWlType/chkBeacon/bssid/getStationInfo(da,sa) 접근이 안전해짐
   // AP essid 경로: tagLen = caplen - rdt->len - 36 이 음수면 getEssid 가
   //   루프가드(index+2<=end, end<index)로 false 반환 -> continue. 안전.

 [--] QListWidget 이중 삽입 (구 U-2 "Critical, double-free")   [소스대조, 정정]
      위치 : mainwindow.cpp 246(생성자에 parent) + 260(addItem)
      Qt 6.10 qlistwidget.cpp:
        QListWidget::insertItem: if (item && !item->view) ... insert
        생성자 QListWidgetItem(view) 가 이미 item->view 를 세팅
      => 뒤의 addItem(newItem) 은 조용한 NO-OP. 중복행/double-free/크래시 없음.
      => 정리: L246 에서 parent 빼고 addItem 으로 통일하든, addItem 1줄 삭제하든 택1.

 [--] presentCount/getRdtInfo OOB (구 C-4 "Critical")          [정정]
      radiotap 은 로컬 드라이버 생성이라 present 비트맵을 공격자가 못 정함.
      0xFF 를 함수에 직접 먹인 "실측"은 실제 입력을 반영하지 못함 => 실전 도달 불가.
      방어적 하드닝 수준(원하면 caplen/rdt->len 상한 전달)으로 강등.

 [--] raw MAC over-read (구 H-3)                                [실측, 정정]
      위치 : mainwindow.cpp 242,256 QString::fromUtf8((char*)event.bssid.mac)
      over-read(=21B) 자체는 사실이나, 저장 대상 LinkedBssid 는 어디서도 읽히지 않는
      dead data(grep: 쓰기 2곳뿐, 읽기 0). 기능 영향/크래시 없음. 정리만.

 [--] 기타 dead/주석 코드: onDaemonOutput 의 type==99/message 경로는 데몬이
      생성하지 않음. runner.cpp 73-86 ACK 경로 주석처리. oldfiles/ protobuf 잔재.
